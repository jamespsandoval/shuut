# iOS release diagnostics

Every App Store or TestFlight build must keep its native symbols and JavaScript
source map together. Apple crash reports alone can show a React Native fatal
exception without the JavaScript message, as Build 11 did.

## Release identity

Use this exact release key in the crash-reporting provider:

`app.replit.shuut@<version>+<ios build number>`

Do not include account IDs, email addresses, handles, post text, audio URLs,
authorization headers, or request bodies in crash events. The allowed default
metadata is app version, iOS build number, release channel, OS/device model, and
the exception message and stack.

## Archive the matching artifacts

After Expo Launch finishes, download the build's iOS dSYMs and the exact
Hermes source map generated by that same build. Put the zipped `*.dSYM.zip` and
the iOS/Hermes `*.map` in one temporary directory, then run:

```sh
pnpm --filter @workspace/shuut-native diagnostics:archive -- \
  --input /path/to/build-diagnostics \
  --output /path/to/durable-private-release-archive \
  --version 1.0.0 \
  --build 12
```

The command fails if either artifact type is absent, if the dSYM does not have
a ZIP signature, or if the source map is not usable version 3 source-map JSON.
It writes a manifest with the operator-supplied release key, byte sizes, and
SHA-256 hashes. Retain that directory for at least as long as the corresponding
build can be installed.

The archive establishes file presence and later byte-for-byte integrity. It
does not prove by itself that the operator selected artifacts from the declared
build. The provider-side UUID and symbolication checks below establish that
association.

When Sentry is connected, configure its Expo and Metro plugins so the build
uploads dSYMs and Hermes maps automatically. Keep this archive as the
independent record used to confirm that the uploaded files match the build.

## Verify symbolication before release

1. Create an internal diagnostics build, never a production build, with:
   - `EXPO_PUBLIC_RELEASE_CHANNEL=diagnostics`
   - `EXPO_PUBLIC_CRASH_PROBE=startup`
2. Launch it once. It must throw
   `SHUUT_DIAGNOSTICS_STARTUP_PROBE_7F4C2A`.
3. In the crash provider, confirm the report has the expected release key and
   build number.
4. Confirm the JavaScript exception message is visible and at least one app
   frame resolves to `lib/startupCrashProbe.ts`, not only a minified bundle
   offset.
5. Confirm the provider reports no missing debug files for the event and that
   its dSYM UUIDs belong to this build.
6. Disable both probe variables, make a fresh production build, archive its
   artifacts, and confirm `pnpm --filter @workspace/shuut-native test:release`.

Never submit a build with the probe variables enabled.
